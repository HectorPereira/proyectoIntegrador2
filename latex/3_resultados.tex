\subsection{Diseño y fabricación}
\subsubsection{Articulaciónes desmontables}

Con base en los lineamientos de tolerancias del apartado~\ref{Tolerancias}, se diseñó y fabricó una articulación desmontable para el brazo robótico. El objetivo fue verificar encastres, juego angular y comportamiento frente a rozamiento en las superficies de contacto.

\vspace{1em}

Inicialmente se construyó con descartes de MDF cortados a láser y herrajes M3. La pieza se sometió a esfuerzos de fricción, corte y rotación para observar desgaste, holguras y deformaciones. El prototipo permitió validar el principio mecánico, pero evidenció pérdida de tolerancia en contactos MDF-MDF bajo uso repetido. 

\begin{figure}[H]
  \centering
  \includegraphics[width=0.7\textwidth]{anexos/Articulacion/V2.png}
  \caption{Sistema de articulación desmontable. Fuente: elaboración própia}\label{fig:articulacionV2}
\end{figure}




Posteriormente se reemplazaron las superficies de contacto por insertos impresos en PLA, configurando una interfaz PLA–PLA en las zonas con rozamiento. Se ajustaron tolerancias según las galgas obtenidas, reduciendo el juego en el conjunto ensamblado y mejorando la repetibilidad. Se documentaron espesores, holguras objetivo y par de apriete de tornillería para su reproducción. Véase figura \ref{fig:corte_pernoV3}



\begin{figure}[H]
  \centering
  \includegraphics[width=0.7\textwidth]{anexos/Articulacion/Perno V3.png}
  \caption{Corte transversal perno --- versión mejorada. Fuente: elaboración própia}\label{fig:corte_pernoV3}
\end{figure}



Se identifican con verde las superficie de contacto que friccionan contra el perno azúl, las cualés tienen un ajuste deslizante con el perno. En amarillo se muestra la pieza que actúa como tope para el seguro del perno. En el modelo anterior se utilizaba una sola pieza que hacía esta función, pero al utilizar este tope (con un ajuste apretado) permite regular la fuerza de ajuste y juego de la articulación. El seguro que se encuentra entre el tope y el perno, este permite montar y desmontar la articulación de manera sencilla.

\subsubsection{Electroimán}
Para realizar la carcasa del electroimán se realiza uso de un torno manual. Hasta tener las medidas concretadas, se dejan un excedente en espesor y longitud para realizar pruebas durante el proceso de prototipado. Cuando se obtengan el resto de valores se dará lugar a una finalización de esta pieza por motivos de reducción de peso.

\vspace{1em}

La bobina del electroimán se construyó utilizando alambre de cobre esmaltado de 0,5 mm de diámetro, enrollado a lo largo de aproximadamente 5 metros para generar el campo magnético necesario. Como núcleo ferromagnético se empleó un tornillo de acero, seleccionado por su alta permeabilidad magnética y disponibilidad. 

\vspace{1em}

Para asegurar la integridad mecánica del devanado y permitir un montaje limpio dentro del efector, se diseñó e imprimió en 3D una carcasa encapsulante, la cual facilita el proceso de bobinado, protege el alambre y permite fijar la bobina de manera estable en la estructura del electroimán. Este encapsulamiento también mejora la manipulabilidad del conjunto y reduce el riesgo de daños por fricción o tensiones mecánicas durante la operación del brazo robótico.

\subsection{Fuente de alimentación}

En lo referente a la electrónica de potencia, se utilizó una fuente ATX de una computadora en desuso para alimentar los motores del sistema. Esta fuente fue seleccionada debido a su capacidad para suministrar líneas estables de 12 V y 5 V, necesarias para los distintos actuadores.

\vspace{1em}

Además, se diseñó e imprimió una carcasa para alojar y proteger la fuente, permitiendo un montaje seguro y una mejor organización del cableado dentro del proyecto, la misma se enciende por un interruptor ubicado en la parte delantera de la carcasa.

\subsection{Interfaz gráfica}
\subsubsection{Selección y justificación de la interfaz gráfica de control}

Se adoptó una aplicación de escritorio como interfaz humano-máquina (HMI) con el objetivo de facilitar el proceso de prototipado y permitir la incorporación rápida de nuevas funcionalidades. Este enfoque proporciona una mayor flexibilidad frente a los paneles físicos, evitando modificaciones en el hardware cada vez que se requieren ajustes en el sistema. Asimismo, la interfaz gráfica permite integrar visualización en tiempo real, ajustes finos de parámetros operativos y funciones avanzadas como la automatización de secuencias.

\subsubsection{Arquitectura distribuida del sistema}

El sistema se diseñó mediante una arquitectura distribuida en la cual la aplicación ejecuta las tareas de control de alto nivel, mientras que el microcontrolador gestiona el control de tiempo real de los actuadores. La comunicación entre ambos módulos se implementó mediante un enlace serial UART utilizando un protocolo textual simplificado. Esta separación permite mantener un comportamiento determinístico en el movimiento de los servomotores, al mismo tiempo que se preserva la flexibilidad y escalabilidad de la capa superior del sistema.

\subsubsection{Modos de operación implementados}

Se definieron dos modos principales de operación:
\begin{itemize}
    \item \textbf{Modo de control manual (modo espejo):} el robot replica directamente los movimientos ejecutados mediante el controlador físico.
    \item \textbf{Modo de control por aplicación:} las consignas de movimiento se generan desde la interfaz gráfica, lo que permite una mayor precisión y la posibilidad de automatizar secuencias.
\end{itemize}

La elección del modo se gestiona mediante lógica interna del sistema, garantizando transiciones suaves y sin interrupciones bruscas.

\subsubsection{Procedimiento de grabación y reproducción de trayectorias}

Se implementó un sistema de muestreo periódico de los ángulos articulares para registrar secuencias de movimiento. Las trayectorias se almacenan en estructuras ordenadas que preservan tanto el valor de cada articulación como el intervalo de muestreo. Para la reproducción, el sistema ejecuta las consignas respetando la cadencia temporal original, lo cual permite replicar movimientos de forma aproximada y consistente.

\subsubsection{Estrategias de seguridad aplicadas}

Con el fin de garantizar la integridad del sistema y del operador, se incorporaron diversas estrategias de seguridad en la capa de software. Entre ellas se incluyen:
\begin{itemize}
    \item Establecimiento de límites de operación por software para cada articulación.
    \item Validación de comandos provenientes de la aplicación para evitar consignas incoherentes.
    \item Implementación de transiciones progresivas entre modos de operación.
    \item Generación de rampas de movimiento al iniciar trayectorias automáticas, reduciendo esfuerzos mecánicos y evitando cambios bruscos.
\end{itemize}

\subsubsection{Integración entre la HMI y el microcontrolador}

La aplicación de escritorio envía comandos en un formato estructurado que el microcontrolador interpreta y ejecuta en tiempo real. De forma complementaria, el microcontrolador retorna información del estado del sistema, la cual es procesada y presentada visualmente al operador. Este mecanismo bidireccional garantiza coherencia entre la interfaz y el estado físico del robot, asegurando una operación confiable y sincronizada.
